Przykład to absolutnie minimalna konfiguracja MESA (26.04.1) dla ewolucji gwiazdy o masie
$1\,M_\odot$ od jednorodnego obłoku H/He (pre-MS) do stygnącego białego karła, ok.~15\,000 kroków.
Obliczenia trwają od poniżej 1~godziny (szybki komputer) do kilku godzin.

\textbf{Od czego zacząć:}


\begin{itemize}
  \item Pracownia komputerowa Fort OA (MESA już zainstalowana): rozdział~\ref{sec:pracownia}.
  \item Własny komputer z Linuksem: rozdział~\ref{sec:linux}. Działa także w maszynie wirtualnej, np. VMware Workstation pod Windows. 
  \item Mac z procesorem Apple Silicon (M1--M4): rozdział~\ref{sec:mac}.
  \item Windows: \textbf{zalecane} WSL (pełna funkcjonalność, z wykresami), rozdział~\ref{sec:wsl}.
        Bez WSL: wersja natywna (eksperymentalna, na razie bez wykresów), rozdział~\ref{sec:win}.
\end{itemize}

\section{Wymagania}\label{sec:wymagania}

\begin{itemize}
  \item Dysk: pełna instalacja MESA to ok.~21~GB, MESA SDK ok.~0.7~GB.
  \item Pamięć: 8~GB RAM to minimalne oficjalne wymagania. Jeżeli w~pliku \texttt{inlist} ustawimy \verb#use_FreeEOS = .false.# (od 12~października 2026 ustawienie domyślne) obliczenia zajmują najwyżej ok.~2.7~GiB (rozdział~\ref{sec:pamiec}).
  Wcześniej sam program zajmował do 7.8~GiB i na komputerach pracownianych z~7.6~GiB obliczenia się zawieszały.
  \item Ścieżki do katalogów z MESA \textbf{nie mogą zawierać spacji}.
  \item MESA SDK w wersji kompatybilnej z użytą wersją MESA (Linux, WSL: TODO; macOS: 26.6.1 z MESA 26.04.1). 
\end{itemize}

\section{Pracownia komputerowa Fort OA}\label{sec:pracownia}

MESA wersja TODO jest zainstalowana systemowo w~\verb!/opt/MESA!. Wystarczającą ilość pamięci powyżej 8~GB mają
w~tej chwili komputery: Cep, Aqr, Eri, Sgr, Hya. 


\textbf{TODO:} \textit{sprawdzić, czy po zmianie z~12~października 2026
(rozdział~\ref{sec:pamiec}) przykład działa na wszystkich komputerach pracowni.}

\begin{enumerate}
\item W konsoli Linuxowej ustawiamy z linii komend zmienne środowiskowe dla MESA SDK i~programu MESA:
\begin{verbatim}
export MESASDK_ROOT=/opt/MESA/mesasdk
source $MESASDK_ROOT/bin/mesasdk_init.sh
export MESA_DIR=/opt/MESA/mesa-24.08.1
\end{verbatim}
\item Aby uniknąć problemów z zapisem plików cache (eos -- równanie stanu, kap --
  nieprzezroczystość, rates -- reakcje jądrowe, ionization -- jonizacja), tworzymy własny katalog (tylko za pierwszym razem)
  i ustawiamy zmienną \texttt{MESA\_CACHES\_DIR}:
\begin{verbatim}
mkdir -p $HOME/.mesa
export MESA_CACHES_DIR=$HOME/.mesa
\end{verbatim}
\item Pracujemy w katalogu \verb!/data/rok4! (zamień \texttt{rok4} na swój rocznik). Testy pokazują,
  że symulacja działa tam ok.~3 razy szybciej niż w~katalogu \verb#$HOME#, ale wyniki nie są
  dostępne na innych komputerach. Praca w katalogu domowym jest możliwa, program po prostu działa wolniej, ale za to wyniki są od razu dostępne na wszystkich stanowiskach pracowni komputerowej.   
\begin{verbatim}
cd /data/rok4
mkdir MESA2027
cd MESA2027
git clone https://github.com/VA00/MESA-minimal-test-1MSun-star.git
cd MESA-minimal-test-1MSun-star
\end{verbatim}
\item Kompilacja i uruchomienie: \verb!./mk!, \verb!./rn! (rozdział~\ref{sec:run}).
\end{enumerate}

\paragraph{Znany problem.} Na komputerach pracowni obliczenia zawieszały się przy kroku 10\,703
(okolice błysku helowego). TODO: Prawdopodobna przyczyna i rozwiązanie: rozdział~\ref{sec:pamiec}.

\paragraph{Zadanie.} Proszę powtórzyć testowy run w katalogach \verb!/data/rok4! oraz \verb!$HOME!
i podać konkretne wartości czasu obliczeń.

\section{Linux (Ubuntu) -- instalacja na własnym komputerze}\label{sec:linux}

Sprawdzone 12~października 2026 na Ubuntu 24.04 (MESA SDK 24.7.1, MESA 24.08.1).

\begin{enumerate}
\item Pobieramy MESA SDK (24.7.1, ok.~209~MB, ok.~8~min) i MESA (24.08.1, ok.~2~GB, ok.~18~min).
  Serwer SDK odrzuca pobieranie z konsoli, dlatego \texttt{wget} „udaje” przeglądarkę Firefox:
\begin{footnotesize}
\begin{verbatim}
mkdir ~/MESA
cd ~/MESA
wget -U firefox \
http://user.astro.wisc.edu/~townsend/resource/download/mesasdk/mesasdk-x86_64-linux-24.7.1.tar.gz
wget https://zenodo.org/records/13353788/files/mesa-24.08.1.zip
\end{verbatim}
\end{footnotesize}
\item Rozpakowujemy SDK i ustawiamy zmienne (bash):
\begin{verbatim}
tar xvfz mesasdk-x86_64-linux-24.7.1.tar.gz -C ~/MESA/
export MESASDK_ROOT=~/MESA/mesasdk
source $MESASDK_ROOT/bin/mesasdk_init.sh
\end{verbatim}
  Powinny pojawić się komunikaty:
\begin{verbatim}
mesasdk_init.sh: checking architecture
mesasdk_init.sh: regenerating headers
mesasdk_init.sh: checking prerequisites
\end{verbatim}
\item Na ogół brakuje kilku programów, o czym informuje komunikat typu:
\begin{verbatim}
mesasdk_init.sh: missing prerequisites:
  C shell Z library X11 library
\end{verbatim}
  Doinstalowujemy je i powtarzamy krok~2 (\texttt{source ...}). Instalujemy też \texttt{git}
  i~\texttt{unzip} (kroki 4 i~7), których może brakować w świeżej instalacji Ubuntu:
\begin{verbatim}
sudo apt install tcsh zlib1g-dev libx11-dev git unzip
\end{verbatim}
\item Rozpakowujemy MESA i ustawiamy kolejne zmienne (liczba wątków według liczby rdzeni,
  rozdział~\ref{sec:bench}):
\begin{verbatim}
cd ~/MESA
unzip mesa-24.08.1.zip
export MESA_DIR=~/MESA/mesa-24.08.1
export OMP_NUM_THREADS=4
\end{verbatim}
\item Opcjonalnie, żeby zmienne ustawiały się przy każdym uruchomieniu terminala, dopisujemy je do
  \verb!~/.bashrc!:
\begin{verbatim}
echo 'export MESASDK_ROOT=~/MESA/mesasdk' >> ~/.bashrc
echo 'source $MESASDK_ROOT/bin/mesasdk_init.sh' >> ~/.bashrc
echo 'export MESA_DIR=~/MESA/mesa-24.08.1' >> ~/.bashrc
echo 'export OMP_NUM_THREADS=4' >> ~/.bashrc
\end{verbatim}
\item Instalacja (kompilacja trwa kilkanaście minut):
\begin{verbatim}
cd $MESA_DIR
./install
\end{verbatim}
  Jeżeli się powiodła, pojawi się dużo gwiazdek i napis:
\begin{verbatim}
************************************************
MESA installation was successful
************************************************
\end{verbatim}
\item Pobieramy przykład:
\begin{verbatim}
cd ~/MESA
git clone https://github.com/VA00/MESA-minimal-test-1MSun-star.git
cd MESA-minimal-test-1MSun-star
\end{verbatim}
  i uruchamiamy go poleceniami \verb!./mk!, \verb!./rn! (rozdział~\ref{sec:run}).
\end{enumerate}

\paragraph{Instalacja na dysku zewnętrznym.} Na systemach plików bez dowiązań symbolicznych (exFAT,
FAT32) SDK i~MESA nie działają. Można je zainstalować na dysku lokalnym, a potem skopiować na dysk
USB z~rozwinięciem dowiązań:
\begin{small}
\begin{verbatim}
rsync -aL --info=progress2 ~/MESA/mesa-24.08.1/ /media/$USER/USB/mesa-24.08.1/
rsync -aL --info=progress2 ~/MESA/mesasdk/ /media/$USER/USB/mesasdk/
\end{verbatim}
\end{small}
i ustawić \texttt{MESA\_DIR} oraz \texttt{MESASDK\_ROOT} na nowe położenie.

\section{macOS (Apple Silicon)}\label{sec:mac}

Aktualizacja: 13 października 2026 (MESA SDK 26.6.1, MESA 26.04.1).

\begin{enumerate}
\item Pobieramy i instalujemy MESA SDK dla Apple Silicon, wersja 26.6.1 (czerwiec 2026), ze strony\\
  \url{http://user.astro.wisc.edu/~townsend/static.php?ref=mesasdk}\\
  plik \texttt{mesasdk-aarch64-macos-26.6.1.pkg}.
  Instalacja jest okienkowa, po kliknięciu na pobraną „paczkę”. SDK trafia do
  \verb!/Applications/mesasdk!. Starsza wersja 24.10.1 już nie działa.
\item Zmienne środowiskowe (domyślna powłoka zsh jest zgodna z bash):
\begin{verbatim}
export MESASDK_ROOT=/Applications/mesasdk
source $MESASDK_ROOT/bin/mesasdk_init.sh
\end{verbatim}
\item Pobieramy MESA (plik zip z Zenodo, \url{https://zenodo.org/records/19722306}). Safari sam
  rozpakowuje archiwum. Cały katalog \texttt{mesa-26.04.1} najlepiej przenieść do \verb!~/MESA!.
  To samo z terminala:
\begin{verbatim}
mkdir ~/MESA
cd ~/MESA
curl -L -O https://zenodo.org/records/19722306/files/mesa-26.04.1.zip
unzip mesa-26.04.1.zip
\end{verbatim}
\item Kolejne zmienne:
\begin{verbatim}
export MESA_DIR=$HOME/MESA/mesa-26.04.1
export OMP_NUM_THREADS=8
export PATH=$PATH:$MESA_DIR/scripts/shmesa
\end{verbatim}
  Żeby ustawiały się automatycznie, dopisujemy powyższe linie (także te z kroku~2) do
  \verb!~/.zshrc!.
\item Instalacja:
\begin{verbatim}
cd $MESA_DIR
./install
\end{verbatim}
\item Aby MESA cokolwiek wyświetlała (okna pgstar), trzeba zainstalować serwer X, np.~XQuartz
  (\url{https://www.xquartz.org}).
\item Pobieramy przykład i uruchamiamy go jak w Linuksie:
\begin{verbatim}
cd ~/MESA
git clone https://github.com/VA00/MESA-minimal-test-1MSun-star.git
cd MESA-minimal-test-1MSun-star
\end{verbatim}
  Czas obliczeń: 135~min przy \texttt{OMP\_NUM\_THREADS=8} na procesorze M3 Max.
\end{enumerate}

\paragraph{Zadanie.} Nowoczesne procesory (Apple M3, M4, ale też np.~Intel i9 285) mają rdzenie typu
„performance” (szybkie, gorące) i~„efficiency” (wolniejsze, chłodniejsze). W Linuksie można
przypisać symulację do wybranych rdzeni poleceniem \texttt{taskset}. Jak zrobić to w macOS?

\section{Uruchomienie przykładu (wszystkie systemy)}\label{sec:run}

\subsection{Komendy programu MESA}

\begin{center}
\begin{tabular}{ll}
\toprule
kompilacja & \verb!./mk! \\
start od początku & \verb!./rn! \\
restart od ostatniego zdjęcia & \verb!./re! \\
restart od zdjęcia \texttt{x500} & \verb!./re x500! \\
sprzątanie kompilacji & \verb!./clean! \\
\bottomrule
\end{tabular}
\end{center}
Obliczenia przerywamy kombinacją \texttt{Ctrl+C}. Pliki restartu są w katalogu \texttt{photos}.

\subsection{Pełna ewolucja}

Po \verb!./rn! po kilku minutach pojawiają się okna z wizualizacją ewolucji gwiazdy. Typowy koniec obliczeń:
\begin{verbatim}
save photos/x986 for model 14986
termination code: log_L_lower_limit

                 runtime (minutes), retries, steps      ...         491     14986
\end{verbatim}
Czas obliczeń zależy od komputera, patrz rozdział~\ref{sec:bench}. Wyniki trafiają do katalogów
\texttt{LOGS} (\texttt{history.data}, profile), \texttt{photos} (zdjęcia do restartów)
i \texttt{png} (wykresy).

W trakcie ewolucji możemy edytować plik \texttt{inlist.pgstar}, w szczególności dodawać i zmieniać różne tryby
wizualizacji wnętrza gwiazdy.






\subsection{Szybki test: 50 kroków od ciągu głównego}\label{sec:zams}

Po kompilacji (\verb!./mk!):
\begin{verbatim}
mkdir ../zams_test
cp star inlist inlist.pgstar history_columns.list rn ../zams_test/
cd ../zams_test
\end{verbatim}
W Windows natywnie:
\begin{small}
\begin{verbatim}
mkdir ../zams_test
Copy-Item star.exe, inlist, inlist.pgstar, history_columns.list, rn.ps1 ../zams_test
cd ../zams_test
\end{verbatim}
\end{small}
W pliku \texttt{inlist} (edytor \texttt{nano inlist} lub \texttt{notepad inlist}) zmieniamy w sekcji
\verb!&star_job!
\begin{verbatim}
  create_pre_main_sequence_model = .false.
\end{verbatim}
a w sekcji \verb!&controls! dopisujemy linijkę
\begin{verbatim}
  max_model_number = 50
\end{verbatim}
Uruchamiamy \verb!./rn!. Poprawny wynik (0 powtórzeń, 50 kroków):
\begin{verbatim}
termination code: max_model_number
                 runtime (minutes), retries, steps        0.10         0        50
\end{verbatim}
Wynik sprawdzony w~Windows natywnie i w~Linuksie (także po zmianie z~12~października 2026),
w~macOS jeszcze nie.


\paragraph{Znane problemy.}
\begin{itemize}
  \item Błąd \verb!Cannot match namelist object name read_extra_pgstar_inlist1!: w pliku
        \texttt{inlist} trzeba zmienić nazwy (w repozytorium już poprawione):
\begin{verbatim}
read_extra_pgstar_inlist1   ->  read_extra_pgstar_inlist(1)
extra_pgstar_inlist1_name   ->  extra_pgstar_inlist_name(1)
\end{verbatim}
  \item Błąd związany z \texttt{adipls} może wynikać ze zmiany nazewnictwa nowych wersji MESA: nie
        ma literki „r”, tylko sam numer wersji.
\end{itemize}

\section{Pamięć i równanie stanu: \texttt{use\_FreeEOS}}\label{sec:pamiec}

\paragraph{Problem.} Na komputerach pracowni (8~GB RAM, system widzi 7.6~GiB) obliczenia
zawieszały się przy kroku 10\,703, w~okolicy błysku helowego.

\paragraph{Pomiar zużycia pamięci.} Aby zmierzyć zużycie pamięci, używamy polecenia
\begin{verbatim}
grep VmRSS /proc/$(pgrep -n star)/status
\end{verbatim}
Wynik jest na rysunku~\ref{fig:pamiec} (niebieska linia). Pamięć rośnie skokami do 7.2~GiB już
przed ciągiem głównym (ok.~600.~model), potem do 7.5~GiB przy zapłonie helu w~jądrze i do 7.8~GiB
przy późnym błysku w~warstwie helowej. To więcej, niż ma komputer na pracowni, nawet bez systemu.
Do kroku 10\,703 obliczenia szły najprawdopodobniej dzięki pamięci wymiany (swap).

Liczba wątków nie ma znaczenia (4 i~24 wątki: ta sama pamięć w~tych samych modelach), wykresy
pgstar zajmują ok.~0.1~GiB. Dlatego wyłączanie wykresów czy zmniejszanie liczby wątków nie pomaga.

\paragraph{Przyczyna.} Które pliki program czyta w~chwili skoku pamięci, pokazuje
\begin{verbatim}
strace -f -e trace=openat -p $(pgrep -n star)
\end{verbatim}
Każdy skok to wczytanie kolejnych tablic równania stanu FreeEOS, czyli plików z~katalogu
\verb!$MESA_DIR/data/eosFreeEOS_data!. Jedna tablica zajmuje w~pamięci 128~MB, a~tablic jest
89 (różne zawartości wodoru $X$ i~metali $Z$), razem ok.~11~GB. MESA wczytuje je w~miarę
potrzeby i~już nie zwalnia.

\paragraph{Rozwiązanie.} W~sekcji \verb!&eos! pliku \texttt{inlist}:
\begin{verbatim}
  use_FreeEOS = .false.
\end{verbatim}
W~obszarze, który obejmowało FreeEOS, MESA używa wtedy tablic OPAL/SCVH (a~poza nimi HELM).
Pamięć: najwyżej 2.7~GiB (pomarańczowa linia). Pełna ewolucja do białego karła przeszła z~pamięcią
ograniczoną do 6~GiB, bez swapu. Tak można na własnym komputerze z~Linuksem sprawdzić, czy
obliczenia zmieszczą się w~mniejszej pamięci, bez maszyny wirtualnej:
\begin{verbatim}
systemd-run --user --scope -p MemoryMax=6G -p MemorySwapMax=0 ./rn
\end{verbatim}

\centering
\includegraphics[width=\textwidth]{mem.png}
\caption{Pamięć programu \texttt{star} w~trakcie ewolucji. Niebieski: z~FreeEOS (do 12~października
2026), pomarańczowy: \texttt{use\_FreeEOS = .false.}. Dolny panel: liczba stref modelu.}

\section{Animacje}\label{sec:anim}

Z plików w katalogu \texttt{png} można utworzyć film programem \texttt{ffmpeg} (w Linuksie jest
częścią MESA SDK). Każdy typ wykresu ma własne pliki: \texttt{HR\_*}, \texttt{Kippenhahn\_*},
\texttt{abund\_*}, \texttt{power\_*}, \texttt{trho\_profile\_*}, \texttt{Summary\_Burn\_*}. Film
robimy z~jednego typu, np.~diagramu H-R (wzorzec \verb!png/*.png! skleiłby wszystkie typy jeden po
drugim):
\begin{verbatim}
# film AVI
ffmpeg -f image2 -pattern_type glob -i 'png/HR_*.png' -c:v libx264 -preset slow \
  -crf 20 -pix_fmt yuv420p -aspect 16:9 -vf "scale=1920:-1" -r 25 HR.avi

# film MKV bezstratny
ffmpeg -f image2 -pattern_type glob -i 'png/HR_*.png' -c:v ffv1 -level 3 \
  -pix_fmt yuv444p -aspect 16:9 -vf "scale=1200:-1" -r 25 HR.mkv

# animacja GIF
ffmpeg -y -f image2 -thread_queue_size 256 -pattern_type glob -i 'png/HR_*.png' \
  -vf "scale=800:-1:flags=lanczos,palettegen" /tmp/palette.png
ffmpeg -y -f image2 -thread_queue_size 256 -pattern_type glob -i 'png/HR_*.png' \
  -i /tmp/palette.png \
  -lavfi "scale=1600:-1:flags=lanczos [x]; [x][1:v] paletteuse" HR.gif
\end{verbatim}
Skrypt \verb!./parallel_movie_encode.sh! tworzy równolegle (też programem \texttt{ffmpeg}) osobny
film AVI dla każdego typu wykresu, który jest w katalogu \texttt{png}.

\section{Windows natywnie: szczegóły i rozwiązywanie problemów}\label{app:win}

Sprawdzone 13~października 2026: Windows~11, AMD Ryzen~9 5900X, 32~GB RAM, MESA 26.04.1,
gfortran 16.1.0, HDF5 2.1.1 i LAPACK 3.12.1 (MSYS2). Ograniczenia: brak wykresów pgstar (MESA zbudowana bez PGPLOT,
\texttt{pgstar\_flag} jest ignorowane), nie są budowane GYRE, ADIPLS, \texttt{binary} i
\texttt{astero}, wyniki nie są identyczne bit w bit z~Linuksem (różnice na poziomie zaokrągleń).

\subsection{Testy modułów (opcjonalnie)}

Po instalacji MESA, w oknie z ustawionymi zmiennymi (kilkanaście minut):
\begin{verbatim}
C:\MESA\MESA-minimal-test-1MSun-star\windows\test_mesa.ps1
\end{verbatim}
Wyniki są porównywane z wzorcami z Linuksa (tolerancja $10^{-8}$). Oczekiwane: \texttt{OK} wszędzie
oprócz \texttt{num} (całkowanie sztywnych równań różniczkowych wzmacnia różnice zaokrągleń do
$10^{-5}$) i \texttt{net} (jedna linia, różnica $5\cdot10^{-7}$).

\subsection{Parametry \texttt{mesa\_env.ps1}}

\texttt{-MesaDir} (inne położenie MESA niż katalog obok repozytorium), \texttt{-Threads}
(liczba wątków, domyślnie liczba rdzeni), \texttt{-Toolchain} (MSYS2 w innym miejscu niż
\verb!C:\msys64!).

\subsection{Co zmieniono względem instalacji na Linuksie}

\begin{enumerate}
\item \textbf{System budowania.} Moduły są kompilowane oryginalnymi makefile'ami MESA, uruchamianymi
  natywnym \texttt{mingw32-make.exe} (receptury wykonuje \texttt{cmd.exe}), z plikiem
  \verb!utils\makefile_header! w wersji dla Windows. Narzędzia z~MESA SDK zastąpiono skryptami
  PowerShell (\texttt{makedepf90.ps1}, \texttt{cp\_if\_newer.ps1}), a bashowe \texttt{install}
  i~\texttt{build\_data\_and\_export} skryptem \texttt{install\_mesa.ps1}. Biblioteka forum (z GYRE)
  jest preprocesowana programem \texttt{fypp}. LAPACK/BLAS i HDF5 pochodzą z~MSYS2 (linkowane
  statycznie). GYRE jest zastąpione stubem.
\item \textbf{Plik C} \verb!utils\private\utils_c_system.c! używa funkcji POSIX, których MinGW nie
  ma w tej postaci (\texttt{mkdir(path, mode)}, \texttt{realpath}, brak \texttt{O\_BINARY}), oraz
  \texttt{rename()}, które w Windows nie nadpisuje istniejącego pliku. Łata jest ujęta
  w \verb!#ifdef _WIN32!.
\item \textbf{Ustawienia regionalne.} libgfortran (MinGW/UCRT) przestawia proces na locale
  użytkownika (\texttt{Polish\_Poland.1250}, przecinek dziesiętny) i w wątkach OpenMP liczby z kropką
  są czytane błędnie. \texttt{mesa\_win\_locale.c} przechwytuje \texttt{setlocale}
  (\verb!-Wl,--wrap=__imp_setlocale!, libgfortran linkowana statycznie) i utrzymuje locale „C”.
\item \textbf{Stos.} Windows daje głównemu wątkowi 2~MB stosu (Linux: 8~MB lub
  \texttt{ulimit -s unlimited}). \texttt{star.exe} jest linkowany z rezerwacją 1~GB
  (\verb!-Wl,--stack,1073741824!), a~wątkom OpenMP \texttt{mesa\_env.ps1} ustawia
  \texttt{OMP\_STACKSIZE=512M}.
\item \textbf{Drobiazgi.} W \verb!chem\make\makefile_base! usunięto \verb!-m %m.mod!
  (\texttt{cmd.exe} traktuje \verb!%m! jak zmienną). Dowiązanie \texttt{pgstar.f90} zastępuje kopia
  \texttt{pgstar\_stub.f90}. \texttt{star.exe} potrzebuje \texttt{libgomp-1.dll}
  i~\texttt{libwinpthread-1.dll} z~\verb!C:\msys64\ucrt64\bin! (dodaje je do \texttt{PATH}
  \texttt{mesa\_env.ps1}).
\end{enumerate}

\subsection{Rozwiązywanie problemów}

\begin{description}
\item[Brak zmiennych środowiskowych] Komunikaty \texttt{MESA\_DIR is not set},
  \texttt{mingw32-make} nie jest rozpoznawane albo okno „nie znaleziono libgomp-1.dll”: w tym oknie
  nie wykonano \verb!. ...\windows\mesa_env.ps1!
  (z kropką na początku). MSYS2 w~innym miejscu niż \verb!C:\msys64!: parametr
  \verb!-Toolchain D:/msys64/ucrt64!.
\item[Skrypty są blokowane („running scripts is disabled on this system”)]
  Jednorazowo zezwalamy na skrypty:
\begin{verbatim}
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
\end{verbatim}
\item[\texttt{pacman}: błędy pobierania pakietów (404, \texttt{failed retrieving file})]
  Nieaktualna baza pakietów: \verb!C:\msys64\usr\bin\pacman.exe -Syu --noconfirm! i ponowna
  instalacja.
\item[\texttt{tar}: \texttt{Error opening archive} przy pliku \texttt{.zip}]
  Przed systemowym \texttt{tar} w \texttt{PATH} jest GNU tar (z Git lub MSYS2). Pełna ścieżka:
  \verb!C:\Windows\System32\tar.exe -xf mesa-26.04.1.zip!.
\item[\texttt{Python 3 not found}, otwiera się Microsoft Store]
  Zainstaluj Pythona i otwórz nowe okno PowerShell. Alias Sklepu można wyłączyć w~\emph{Ustawienia
  → Aplikacje → Zaawansowane ustawienia aplikacji → Aliasy wykonywania aplikacji}.
\item[Pierwsze uruchomienie jest bardzo wolne]
  Tworzenie plików cache (jednorazowo). Rozpakowywanie i kompilację spowalnia też antywirus.
  Można (jako administrator) wyłączyć skanowanie katalogu \verb!C:\MESA!.
\end{description}
